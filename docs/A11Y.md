# Auditoria de Acessibilidade — P.A.D.H.

**Data:** 2026-07-13
**Escopo:** `src/**` (código-fonte da SPA)
**Método:** varredura estática do código (ripgrep + leitura dirigida). Contraste de cor **não foi medido em runtime** — recomenda-se rodar Lighthouse/axe-core na preview para confirmar os itens marcados como "Aviso" de contraste.

## TL;DR

O projeto acerta em vários pontos (imagens com `alt`, `Label htmlFor` no login, `role="region"` + teclado no `NetflixCarousel`, nenhum `onClick` em `div`/`span` sem role). Os problemas recorrentes são:

- **Botões icon-only sem `aria-label`** em componentes de UI reutilizados (StreamingCard, NotificationCenter, text-reader, ConfigGuidePage).
- **`<main>` duplicado** em `SessaoView.tsx` (a página já é renderizada dentro de `PageLayout`, que injeta seu próprio `<main>`).
- **Uso extensivo de `min-h-screen`/`h-screen`** em vez de `min-h-dvh` (~21 ocorrências) — causa saltos em mobile com URL bar.
- **Inputs nativos em `Prontuario.tsx` sem associação `label htmlFor` / `id`** — o componente `Field` renderiza o `<label>` visualmente mas sem vínculo programático.
- **Cores de baixo contraste** (`text-white/20`–`/50`, `text-muted-foreground/50`) sobre fundos escuros em várias páginas.
- **`autoFocus`** em `<textarea>` fora de modal em `SessaoView.tsx`.

Nada catastrófico, mas o teclado + leitor de tela ficam inconsistentes em fluxos importantes (dashboard, sessão, prontuário).
